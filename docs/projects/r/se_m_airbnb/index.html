2.3 Task 4.2: Spatial Interpolation of AirBnb Prices via Inverse Distance Weighting (IDW)

While KDE estimates the density of point occurrences, it does not show how property values vary across space. To construct a continuous surface of AirBnb prices (\hat{z}(x) = \sum_i w_i z_i / \sum_i w_i), we apply Inverse Distance Weighting (IDW) interpolation [3], [4]:

  1. Create a regular target grid (mad.grid): A 100 \times 100 grid (10,000 evenly spaced prediction centres) spanning the bounding box of mad_abb.
  2. Compute IDW predictions: Use gstat::idw() with nmax = 150 nearest neighbours for both raw USD prices (price_usd ~ 1) and log-transformed prices (log1p_price_usd ~ 1).
  3. Render the interpolated raster surfaces: Map the predicted values (var1.pred) across the grid.
Code 
# 1. Create a 100 x 100 regular grid of cell centres over Madrid
mad.grid <- mad_abb %>%
  st_bbox() %>%
  st_as_sfc() %>%
  st_make_grid(
    n = 100,
    what = "centers"
  ) %>%
  st_as_sf() %>%
  cbind(., st_coordinates(.))

# Ensure identical CRS between source locations and target grid
st_crs(mad.grid) <- st_crs(mad_abb)

# 2. Fit IDW for raw price_usd (nmax = 150 nearest neighbours)
idw.raw <- idw(
  price_usd ~ 1,
  locations = mad_abb,
  newdata = mad.grid,
  nmax = 150
) %>%
  cbind(st_coordinates(.))

# 3. Fit IDW for log1p_price_usd (nmax = 150 nearest neighbours)
idw.log <- idw(
  log1p_price_usd ~ 1,
  locations = mad_abb,
  newdata = mad.grid,
  nmax = 150

  cbind(st_coordinates(.))

3.3 Task 5.3: Predictive Check Analysis & Model Comparison

To evaluate how well each model captures the true data-generating process, we perform two levels of Predictive Performance Checks (PPC) following [5]:

  1. Point-Estimate Predictive Check: Comparing the empirical kernel density of the deterministic fitted values (\hat{y}_i = X_i\hat{\beta}) against the observed outcome distribution (y_i).
  2. Simulated Predictive Check (Inferential + Predictive Uncertainty): Using arm::sim() to draw posterior parameter realisations (\tilde{\beta}, \tilde{\sigma}) and simulating 250 synthetic outcome vectors \tilde{y} \sim \mathcal{N}(X\tilde{\beta}, \tilde{\sigma}^2).

Now we define the generate_draw() simulation function to incorporate both inferential uncertainty (uncertainty in \hat{\beta}) and predictive uncertainty (the error variance \hat{\sigma}^2), generating n = 250 simulated realisations for each model.

Code 
generate_draw <- function(m) {
  # Set up predictors matrix
  x <- model.matrix(m)
  # Obtain draws of parameters (inferential uncertainty)
  sim_bs <- sim(m, 1)
  # Predicted value
  mu <- x %*% sim_bs@coef[1, ]
  # Draw realization incorporating residual sigma (predictive uncertainty)
  n <- length(mu)
  y_hat <- rnorm(n, mu, sim_bs@sigma[1])
  return(y_hat)
}

Discussion and Model Selection:

  1. Explanatory Power (R^2) and Coefficient Interpretation:
    • In both models, accommodates, bathrooms, and bedrooms have statistically significant positive effects on price (p < 0.001), whereas beds has a statistically significant negative coefficient holding the other predictors constant. This negative partial effect of beds arises because, for a fixed number of bedrooms and guests (bedrooms and accommodates held constant), adding more beds indicates shared/crowded sleeping arrangements (e.g., hostels or subdivided rooms), which command lower nightly rates.
    • However, the raw price model (ba.price) explains only 2.3% of the variance in price (R^2 = 0.0228), with a massive residual standard error of $358.89.
    • By contrast, the log-price model (ba.log_price) more than doubles the explained variance to 24.4% (R^2 = 0.244). Its coefficients have a clean multiplicative (semi-elasticity) interpretation: each additional guest accommodated increases price by approximately 22%, an additional bathroom increases price by -4.4%, an additional bedroom adds 12.3%, and an extra bed (holding capacity and bedrooms constant) reduces price by 6.1%.
  2. Predictive Check Comparison (Why the Log-Price Model is Preferred):
    • Failure of the Raw Price Model: Because price_usd has extreme positive outliers, the Gaussian error assumption \epsilon_i \sim \mathcal{N}(0, \sigma^2) inflates \hat{\sigma} to $358.9. Consequently, the 250 simulated draws (Figure 2.2, left) form a flat, wide normal curve that completely misses the sharp empirical peak around $50–$80 and assigns substantial probability mass to impossible negative prices (left of the dashed blue line at $0).
    • Superiority of the Log-Price Model: In the log-price specification (Figure 2.2, right), while the deterministic point estimates (black curve) are naturally narrower than the observed data (since \text{Var}(\hat{y}) < \text{Var}(y)), the 250 simulated draws (grey band) closely envelope the actual empirical distribution (red curve) in location, spread, and symmetry. Furthermore, exponentiating log-price predictions (\hat{P}_i = \exp(\widehat{\log P_i}) - 1) guarantees strictly positive price predictions. Therefore, the log-price model (ba.log_price) is strongly preferred.

### Task 4.2: Spatial Interpolation of AirBnb Prices via Inverse Distance Weighting (IDW)

While KDE estimates the density of *point occurrences*, it does not show how property *values* vary across space. To construct a continuous surface of AirBnb prices ($\hat{z}(x) = \sum_i w_i z_i / \sum_i w_i$), we apply Inverse Distance Weighting (IDW) interpolation [@comber2015; @cressie2015statistics]:

1. **Create a regular target grid (`mad.grid`)**: A $100 \times 100$ grid (10,000 evenly spaced prediction centres) spanning the bounding box of `mad_abb`.
2. **Compute IDW predictions**: Use `gstat::idw()` with `nmax = 150` nearest neighbours for both raw USD prices (`price_usd ~ 1`) and log-transformed prices (`log1p_price_usd ~ 1`).
3. **Render the interpolated raster surfaces**: Map the predicted values (`var1.pred`) across the grid.

```{r idw_grid_and_interpolation, results='hide'}

mad.grid <- mad_abb %>%
  st_bbox() %>%
  st_as_sfc() %>%
  st_make_grid(
    n = 100,
    what = "centers"

  cbind(., st_coordinates(.))

# Ensure identical CRS between source locations and target grid
st_crs(mad.grid) <- st_crs(mad_abb)

### Task 5.3: Predictive Check Analysis & Model Comparison

To evaluate how well each model captures the true data-generating process, we perform two levels of **Predictive Performance Checks (PPC)** following @gelman2006data:

1. **Point-Estimate Predictive Check**: Comparing the empirical kernel density of the deterministic fitted values ($\hat{y}_i = X_i\hat{\beta}$) against the observed outcome distribution ($y_i$).
2. **Simulated Predictive Check (Inferential + Predictive Uncertainty)**: Using `arm::sim()` to draw posterior parameter realisations ($\tilde{\beta}, \tilde{\sigma}$) and simulating 250 synthetic outcome vectors $\tilde{y} \sim \mathcal{N}(X\tilde{\beta}, \tilde{\sigma}^2)$.

Now we define the `generate_draw()` simulation function to incorporate both **inferential uncertainty** (uncertainty in $\hat{\beta}$) and **predictive uncertainty** (the error variance $\hat{\sigma}^2$), generating $n = 250$ simulated realisations for each model.

```{r fig_ppc_sim, fig.width=11, fig.height=5.2, fig.cap="Figure 2.2: Full Predictive Check with 250 Simulated Realisations (Grey) for the Raw Price Model (left) and Log-Price Model (right)."}
generate_draw <- function(m) {
  # Set up predictors matrix
  x <- model.matrix(m)
  # Obtain draws of parameters (inferential uncertainty)
  sim_bs <- sim(m, 1)
  # Predicted value
  mu <- x %*% sim_bs@coef[1, ]
  # Draw realization incorporating residual sigma (predictive uncertainty)
  n <- length(mu)
  y_hat <- rnorm(n, mu, sim_bs@sigma[1])
  return(y_hat)
}

**Discussion and Model Selection:**

1. **Explanatory Power ($R^2$) and Coefficient Interpretation**:
   - In both models, `accommodates`, `bathrooms`, and `bedrooms` have statistically significant positive effects on price ($p < 0.001$), whereas `beds` has a statistically significant negative coefficient holding the other predictors constant. This negative partial effect of `beds` arises because, for a fixed number of bedrooms and guests (`bedrooms` and `accommodates` held constant), adding more beds indicates shared/crowded sleeping arrangements (e.g., hostels or subdivided rooms), which command lower nightly rates.
   - However, the **raw price model (`ba.price`)** explains only **`r round(summary(ba.price)$r.squared * 100, 1)`%** of the variance in price ($R^2 = `r round(summary(ba.price)$r.squared, 4)`$), with a massive residual standard error of **\$`r round(summary(ba.price)$sigma, 2)`**.
   - By contrast, the **log-price model (`ba.log_price`)** more than doubles the explained variance to **`r round(summary(ba.log_price)$r.squared * 100, 1)`%** ($R^2 = `r round(summary(ba.log_price)$r.squared, 4)`$). Its coefficients have a clean multiplicative (semi-elasticity) interpretation: each additional guest accommodated increases price by approximately **`r round(coef(ba.log_price)["accommodates"] * 100, 1)`%**, an additional bathroom increases price by **`r round(coef(ba.log_price)["bathrooms"] * 100, 1)`%**, an additional bedroom adds **`r round(coef(ba.log_price)["bedrooms"] * 100, 1)`%**, and an extra bed (holding capacity and bedrooms constant) reduces price by **`r abs(round(coef(ba.log_price)["beds"] * 100, 1))`%**.

2. **Predictive Check Comparison (Why the Log-Price Model is Preferred)**:
   - **Failure of the Raw Price Model**: Because `price_usd` has extreme positive outliers, the Gaussian error assumption $\epsilon_i \sim \mathcal{N}(0, \sigma^2)$ inflates $\hat{\sigma}$ to \$`r round(summary(ba.price)$sigma, 1)`. Consequently, the 250 simulated draws (Figure 2.2, left) form a flat, wide normal curve that completely misses the sharp empirical peak around \$50–\$80 and assigns substantial probability mass to **impossible negative prices** (left of the dashed blue line at \$0).
   - **Superiority of the Log-Price Model**: In the log-price specification (Figure 2.2, right), while the deterministic point estimates (black curve) are naturally narrower than the observed data (since $\text{Var}(\hat{y}) < \text{Var}(y)$), the 250 simulated draws (grey band) closely envelope the actual empirical distribution (red curve) in location, spread, and symmetry. Furthermore, exponentiating log-price predictions ($\hat{P}_i = \exp(\widehat{\log P_i}) - 1$) guarantees strictly positive price predictions. Therefore, the **log-price model (`ba.log_price`) is strongly preferred**.

### Task 6.1: Baseline Non-Spatial Log-Price Model (`m1`)

We begin with the baseline non-spatial model explaining `log1p_price_usd` solely through structural property attributes:

$$
\log(P_i) = \alpha + \beta_1 Acc_i + \beta_2 Bath_i + \beta_3 Bedr_i + \beta_4 Beds_i + \epsilon_i
$$

```{r ch6_m1}
m1 <- lm(log1p_price_usd ~ accommodates + bathrooms + bedrooms + beds, data = mad_abb)
summary(m1)
```

**Interpretation (`m1`):**
All four structural predictors are highly statistically significant ($p < 0.001$), explaining **`r round(summary(m1)$r.squared * 100, 2)`%** of log-price variation. However, `m1` assumes a single global intercept ($\hat{\alpha} = `r round(coef(m1)[1], 3)`$) across all of Madrid, ignoring unobserved neighbourhood prestige, accessibility, and locational amenities, which become absorbed into the error term $\epsilon_i$.

### Task 6.2: Spatial Fixed Effects at the Neighbourhood Level (`m2`)

To account for **spatial heterogeneity** at the neighbourhood scale, we allow the intercept $\alpha_r$ to vary across each neighbourhood $r \in \{1, \dots, 128\}$ by introducing neighbourhood indicator variables without a global constant (`- 1`):

$$
\log(P_i) = \alpha_r + \beta_1 Acc_i + \beta_2 Bath_i + \beta_3 Bedr_i + \beta_4 Beds_i + \epsilon_i
$$

```{r ch6_m2}
m2 <- lm(
  log1p_price_usd ~ neighbourhood + accommodates + bathrooms + bedrooms + beds - 1,
  data = mad_abb
)

# Display the structural property coefficients from the Spatial FE model
round(tail(summary(m2)$coefficients, 4), 4)
cat("Spatial FE R-squared:", round(summary(m2)$r.squared, 4),
    "| Adjusted R-squared:", round(summary(m2)$adj.r.squared, 4), "\n")
```

We now extract the estimated neighbourhood fixed effects ($\hat{\alpha}_r$) and map them to visualise Madrid's **"Geography of Desirability"**.

### Task 6.3: Spatial Regimes at the Neighbourhood Level (`m3`)

Spatial fixed effects (`m2`) allow only the intercept ($\alpha_r$) to vary geographically while restricting the slope parameters ($\beta_1, \dots, \beta_4$) to be uniform across Madrid. **Spatial regimes (`m3`)** generalise spatial heterogeneity by allowing both the intercept and all structural slope coefficients to vary across neighbourhoods:

$$
\log(P_i) = \alpha_r + \beta_{r1} Acc_i + \beta_{r2} Bath_i + \beta_{r3} Bedr_i + \beta_{r4} Beds_i + \epsilon_{ri}
$$

```{r ch6_m3}
mad_abb$one <- 1

m3 <- lm(
  log1p_price_usd ~ 0 + (one + accommodates + bathrooms + bedrooms + beds):(neighbourhood),
  data = mad_abb
)

cat("Spatial Regimes R-squared:", round(summary(m3)$r.squared, 4),
    "| Adjusted R-squared:", round(summary(m3)$adj.r.squared, 4), "\n")
```

Let us compare the nested progression from `m1` (Pooled OLS) to `m2` (Spatial Fixed Effects) to `m3` (Spatial Regimes) using an $F$-test (`anova`) and visualise the distribution of neighbourhood-specific slope estimates $\hat{\beta}_{rk}$ across Madrid.

```{r anova_heterogeneity}

```

### Task 6.4: Spatial Weights Matrix & Exogenous Spatial Lag Model (`m4` & `m5`)

Unlike spatial heterogeneity (which links outcomes to administrative areas), **spatial dependence** captures how observations interact directly across distance [@anselin2014modern; @gibbons2014spatial]. We construct a row-standardised $k$-nearest neighbours ($k = 50$) spatial weights matrix $W$, where $w_{ij} = 1/50$ if listing $j$ is among the 50 closest properties to listing $i$, and $w_{ij} = 0$ otherwise.

```{r build_knn_weights}
# Construct k = 50 nearest-neighbour spatial weights matrix
hnn <- mad_abb %>%
  st_coordinates() %>%
  as.matrix() %>%
  knearneigh(k = 50)

hnb <- knn2nb(hnn)
hknn <- nb2listw(hnb, style = "W")
hknn
```

First, we verify the presence of global spatial autocorrelation in `log1p_price_usd` and in the baseline OLS residuals (`m1`) using Moran's $I$.

```{r moran_tests}
moran_price <- moran.test(mad_abb$log1p_price_usd, hknn)
moran_res <- lm.morantest(m1, hknn)

cat("Moran's I on log1p_price_usd:", round(moran_price$estimate[1], 4),
    "(p-value:", format.pval(moran_price$p.value), ")\n")
cat("Moran's I on Baseline m1 Residuals:", round(moran_res$estimate[1], 4),
    "(p-value:", format.pval(moran_res$p.value), ")\n")
```

**Motivation for the Spatial Lag Variable(s):**
We motivate two complementary **Exogenous Spatial Lag (SLX)** models:

1. **Spatial Lag of Bathrooms (`w_bathrooms`, Model `m4`)**: Following the course framework in Chapter 6, the number of bathrooms in a property serves as a proxy for housing size, build quality, and luxury status. The spatial lag $W \cdot \text{Bath}_i = \sum_j w_{ij} \text{Bath}_j$ measures the average number of bathrooms among the 50 nearest surrounding AirBnb listings. If a property is surrounded by large, high-end apartments, positive neighbourhood status externalities and local market comparables should raise its nightly price even holding its own structural characteristics constant:
   $$
   \log(P_i) = \alpha + \beta_1 Acc_i + \beta_2 Bath_i + \beta_3 Bedr_i + \beta_4 Beds_i + \beta_5 Bath_{\text{lag}-i} + \epsilon_i
   $$
2. **Spatial Lag of Guest Capacity (`w_accommodates`) & Distance to El Retiro (`km_to_retiro`, Model `m5`)**: In Madrid, proximity to the city's premier green/cultural landmark (`km_to_retiro`) and the surrounding density of large tourist accommodations (`w_accommodates`) alongside `w_bathrooms` capture both local housing prestige and urban centrality externalities.

```{r ch6_slx_models}

mad_abb$w_accommodates <- lag.listw(hknn, mad_abb$accommodates)

# Model m4: Baseline + Spatial lag of bathrooms (w_bathrooms)

  log1p_price_usd ~ accommodates + bedrooms + beds + bathrooms + w_bathrooms,
  data = mad_abb
)
summary(m4)

# Model m5: Extended spatial model adding w_accommodates and km_to_retiro

  log1p_price_usd ~ accommodates + bedrooms + beds + bathrooms + w_bathrooms + w_accommodates + km_to_retiro,
  data = mad_abb
)
summary(m5)
```
